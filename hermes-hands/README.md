# Hermes Hands

Help someone's computer from your phone. In witness mode they see each command before it runs and hold the off switch.

Hermes runs on a Linux or WSL gateway. A small agent on a paired Windows or Linux computer receives signed terminal, file, checkup, and screenshot requests over outbound HTTPS. The device has no inbound listening port. Offline, revoked, and unreachable device targets fail closed.

## Witness mode

The person at the computer starts `hermes-hands serve --witness` in an interactive terminal, reads who wants to help and what they can do, and types `Y` and presses Enter to consent. They see timestamped command text and outcomes, can type `H` and press Enter to send the helper a message, and can type `S` and press Enter to stop. Sessions end after 30 minutes and write a text receipt plus a signed JSON receipt.

Optional `H` help requires the gateway owner to run `hermes config set plugins.entries.hermes-hands.allow_gateway_injection true` in the intended Hermes profile and restart the gateway, plus a saved owner chat origin from `/hands use <name>`. Setup prints this opt-in command but never enables it. The permission belongs at the plugin entry root, not under `settings`. Leave it disabled if device help text should not start agent turns. `hermes hands doctor` reports `WARN` when this permission is absent, false, or a string, without changing its exit status; other Hands features do not require it.

Help text is filtered, capped at 200 characters, and quoted as untrusted data in a user-role model turn in the saved helper conversation. It is not a fixed direct notification. Asking the model to relay it does not enforce a no-tool boundary; device help remains a prompt-injection surface. Acceptance by the gateway is not proof of delivery to Telegram.

During an active witness session the gateway hook blocks every tool that is not on a short safe list or the approval list. Every `terminal`, `read_file`, `search_files`, `write_file`, `patch`, `vision_analyze`, `video_analyze`, `hands_checkup` and `hands_screenshot` call needs the helper's approval, read only commands included, and each step needs its own approval. The hook blocks shell metacharacters, script launchers and shell state builtins, patch directives, non-replace patches, common startup persistence that would outlast the 30 minute session (startup and autostart folders, LaunchAgents, shell profiles, cron, registry Run keys and imports, scheduled task creation, `systemctl enable`, and any terminal command that names a startup path), and arguments with hidden characters. Text Hermes would redact on the approval card and credential patterns Hands recognizes are refused, including beyond a write preview. Other secrets are shown in cleartext on the card and can run if approved. Ordinary names such as `keyboard.txt` are allowed. Other logon methods, such as `sc create` or the `UserInitMprLogonScript` registry value, are not blocked and reach the helper's approval. Witness device jobs need a human yes even when approvals are off, yolo is on, or an unattended context approves automatically. The transport selected with `security.approval.transport` must ask a human; a plugin transport can answer automatically, and Hands counts its response as approval. The gateway refuses any command that is not what the approval showed, for example one another plugin changed after the approval; a `patch` must replace exactly one exact copy of its `old_string` unless the approved call has `replace_all=true`, and a `write_file` or `patch` needs a full path such as `~/notes.txt`. The whole approval text must fit in 300 UTF-16 units after surface escaping and wrapping, or 500 on Telegram after core HTML escaping; a longer call is refused, not shortened, and the refusal names the longest argument. Prefer short `~/` paths. Session and Always on a witness approval do not carry over, and Always leaves an unused `command_allowlist` entry the owner can delete.

Screenshots work after a normal install, but only with the person's yes for each shot and only on a desktop session; a headless Linux machine has no screen to capture. They need session permission and fresh local consent for every capture. A screenshot request expires after 30 seconds without an answer.

`hands_checkup` returns fixed structured health facts. Windows print queues and known reboot markers are supported. Pending Windows Update availability is unsupported. Five Windows troubleshooting playbooks start with diagnostics and ask for approval before a repair.

The console shows every device job, including core's one-time shell snapshot setup. Core also runs login startup code and sources and refreshes its shell snapshot under the call's approval. These inherited shell jobs are not separately approved. The exact-execution guarantee covers the approved command and file operations, within that runtime envelope.

## Install and configure

Install Hermes 0.23.1 or later on the gateway. The declared floor is `>=0.23.1`. Once Hermes Hands is listed in the plugin catalog, install and enable the reviewed plugin with `hermes plugins install hermes-hands --enable`. The plugin is version 0.2.1; the device package stays at 0.2.0. Then run `hermes hands setup`, apply its backend and placement settings, and start the dashboard on loopback. A device on another machine requires the HTTPS relay route described in the [full setup guide](../README.md#gateway).

Device non-test files are byte-identical to `7e078a50d3a09066aa3e95c3c1a86a9ec221996b` except `executor.py`: if the agent died before a guardian acknowledgement write, the write could fail and skip job-group cleanup. The guardian loop now uses `try/finally` so an acknowledgement write failure still invokes cleanup for registered job groups; its process identity checks are unchanged. The device version remains 0.2.0, but this pinned build differs from the published v0.2.0 tag.

The device needs Python 3.11 or later and Bash. Windows uses Git for Windows. Install the device agent from this repository with `pipx install "git+https://github.com/Ridwannurudeen/hermes-hands-plugin@f5ecec6a4c162e56a33a0f72edc2c6d476bc4afb#subdirectory=device"` (the commit with the guardian cleanup fix, pinned by its full 40 character SHA), which needs Git. To keep its key in the OS keyring, also run `pipx inject hermes-hands "keyring>=24,<26"`. The package is not on PyPI; use the pinned Git URL above. Pair using the command printed by `/hands pair <name> --owner-label "<helper name>"`, start `hermes-hands serve --witness`, and select it from a direct owner chat with `/hands use <name>`. Run only one device agent per device home.

For the Desktop pane, open **Capabilities > Plugins**, search for **Hands**, and enable the **Desktop** part of **Hermes Hands**. It starts disabled in a fresh browser origin. Open a conversation to select its target or pair a device; the status chip follows that conversation's target.

See the [full guide](../README.md) for prerequisites, nginx configuration, policy acceptance after upgrades, doctor checks, receipt verification, data retention, threat model limits and uninstall steps.

Reading a PDF or Office document transfers the whole file to the gateway before extraction, even when a page was requested with `offset` and `limit`. The person's console shows the whole-file transport command. Core can wrap a Hands read refusal in a document-extraction or unavailable-terminal error.

## Limits and data handling

Text Hermes would mask on the approval card is refused so the person never sees different text from what runs, for example `token: Optional[str]`. Witness calls refuse text Hermes would mask, non-placeholder quoted credential values, token prefixes, Bearer values, key blocks, password flags, credential URLs and long or high-entropy values, including beyond a write preview; plain words and keyword arguments in a recognised source file, with or without spaces around `=`, are treated as variable references unless another refusal rule matches; in other files and in terminal commands, a bare word assigned to a secret-looking name is refused. Shell files (`.sh`, `.bash`, `.zsh`) still refuse no-space assignments, as do environment-lookup lookalikes such as `os.environXYZ123`. The source-file rule is based on the file extension, so text that looks like configuration inside a source file is treated as source. Keyword arguments whose value is a bare name, such as `token=token` inside `Client(token=token, api_key=api_key)` or `password=True`, can be masked by Hermes' own approval display and are refused so the card matches; the spaced form `password = True` works, but `Client(token = token, api_key = api_key)` is still masked and refused.

In a witness session, an omitted or null terminal `timeout` for a foreground command becomes one explicit default from the public configuration bridge (180 seconds when unset), shown on the approval card and dispatched unchanged. Set an explicit `timeout` to choose another value. Preserving the scoped profile default needs a public accessor; see [ask 9](../docs/HOOK-REQUEST-ISSUE.md). A background command has no time limit: in a witness session an explicit `timeout` is refused; leave out `timeout`; press S to stop it. Its approval card shows `background=true` and the no-time-limit statement without a timeout.

The device runs with its logged in user's permissions. This is not a sandbox and does not protect against a compromised helper account or gateway. Plain `hermes-hands serve` has no local consent, transcript or stop prompt; use `--witness` when someone else is at the computer. Linux detached processes can survive a stop. Native Windows and Linux under WSL2 were tested live; macOS devices and native Windows gateways are unsupported. The service installer supports Windows Task Scheduler; witness mode requires a real interactive terminal.

Command text is printed and saved in receipts and can contain sensitive arguments or file content. Receipts do not include command output or prove exactly which files changed, and a hard kill of the agent leaves no receipt. Device output logs are stored locally. Screenshots are cached on the gateway, sent to the configured vision model when described, and sent to the chat platform when delivered. The device key stays in its OS keyring when the optional keyring package is installed, otherwise in a protected local file. The gateway stores public device keys and pairing metadata, and obtains its relay seed through Hermes's declared secret configuration.

Hermes Hands registers a terminal backend, dashboard authentication provider, tools, chat and CLI commands, a skill, a `pre_tool_call` hook, and a `tool_execution` middleware that carries the hook decision into the call. Two names outside Hermes's public plugin list are still imported: `register_token_route` for the device routes and `LocalEnvironment` for the `server` target. Once a conversation has used a terminal or file tool, including native server file operations, it cannot switch target. Start a new conversation with `/new`, then `/hands use <target>`; before the first terminal or file-tool execution, any target switch is allowed. Switching pauses while a call is pending; a first attempt that is declined or refused before execution releases that guard. Core keeps per-session file-tool caches and the recorded working folder from the previous machine, and no published seam clears them; see [ask 7](../docs/HOOK-REQUEST-ISSUE.md). Witness writes and patches still need full paths. The [upstream hook request](../docs/HOOK-REQUEST-ISSUE.md) describes the missing public seams. Hermes's dashboard token-provider scope limitation and the full trust model are disclosed in the [security model](../README.md#security-model).

No telemetry is collected. Checkup network probes resolve `example.com` and connect to 1.1.1.1, 8.8.8.8 and 9.9.9.9 on port 443. For the live checks and what remains untested, see [live verification](../README.md#live-verification).

## Verification

CI runs the full automated suite on Hermes 0.23.1. Witness tests cover single query, cron and unattended approve and deny modes, finite unattended turns, a normal human yes, and secret refusal against core redaction.

From the repository root, using an environment with Hermes's test dependencies:

```sh
PYTHONPATH=/path/to/hermes-agent python -m pytest hermes-hands/tests device/tests -q -p no:cacheprovider
```

`hermes plugins validate` warns about those two imports, and reports that dashboard authentication runs in the dashboard process. The live checks in the full guide ran on earlier builds of 0.2.0 and say which parts of this build still need a live run.
