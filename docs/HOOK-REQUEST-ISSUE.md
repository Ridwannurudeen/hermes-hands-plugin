# Hook request: public seams for terminal backend plugins

This is a draft issue for NousResearch/hermes-agent. It has not been posted. It lists every place where Hermes Hands relies on Hermes internals, and the public interface that would replace each one.

**Title:** Plugin seams for terminal backend plugins (token routes, local environment, session cwd, file-tool caches, approval state, hook registry, message injection) and provider-scoped token routes

**Body:**

Hermes Hands is a terminal backend plugin. It runs Hermes's terminal and file tools on a computer the user pairs, while Hermes stays on their gateway, and it adds a witness mode in which the helper approves every tool call that reaches the device. It uses public surfaces wherever it can. The rest is listed here, grouped by what it is for. File references name the module and function, not line numbers, because the lines move between commits; `hermes plugins validate hermes-hands` prints the current file and line of each import.

Private core imports that `hermes plugins validate` flags under rule 9:

- `hermes_cli.dashboard_auth.token_auth.register_token_route` (`hermes-hands/__init__.py`, `register`)
- `tools.terminal_scope.build_profile_terminal_scope` (`hands/commands.py`, `terminal_backend`)
- `tools.environments.base.FileFetchError` (`hands/environment.py`, MEDIA fetch refusal during a witness session)
- `tools.environments.local.LocalEnvironment` (`hands/environment.py`, the `server` target)
- `tools.process_registry_env_log.log_delta_command` (`hands/environment.py`, recognising core's background log poll)
- `tools.file_tools_read_tracking.notify_other_tool_call` (`hands/environment.py`, target change)
- `tools.approval.get_current_session_key` (`hands/environment.py`, three sites)
- `tools.terminal_tool`: `get_session_cwd`, `record_session_cwd`, `_get_env_config` and `resolve_task_overrides` (`hands/environment.py`)
- `tools.file_tools_paths._configured_terminal_cwd` (`hands/environment.py`)
- `tools.terminal_tool_lifecycle.get_active_env` (`hands/environment.py`, target change)
- `agent.redact.redact_approval_display` and `agent.redact.sanitize_command_for_display` (`hands/witness.py`, `_display_problem`)
- `tools.arg_coercion.coerce_tool_args` (`hands/witness.py`, `_coerced`)
- `tools.approval_context`: `_approval_session_id` and `_approval_tool_call_id` (`hands/client.py`, finding the running call when Hermes Desktop copies the call context before the tool body runs)

Couplings the static check does not flag:

- `tools.file_tools.clear_file_ops_cache` (`hands/environment.py`), skipped by the check because `hands/tools.py` shadows the bare name `tools`.
- `tools.approval.is_approval_bypass_active_for_session`, `tools.approval._yolo_active` and `tools.approval._unattended_contexts` (`hands/witness.py`, `_approval_bypassed`), skipped for the same reason.
- `ctx._manager._hooks` and `ctx._manager._middleware` (`hands/witness.py`, `_other_hooks`).
- `ctx._manager.has_gateway_message_injector` (`hands/client.py`, help poller).
- `_help_context._gateway_injection_allowed` (`hands/relay.py`, help route). The validator reports this one as a private attribute access.
- A call-frame check for `tools.file_operations` (`hands/environment.py`, `_called_from`).

I would rather ask for public seams than keep these, so here they are.

1. **A plugin way to mark its own dashboard routes as token routes.** The paired device and the gateway's loopback client call routes under `/api/plugins/hermes-hands/` with a bearer token. Today the only way to opt those exact paths into the token seam is `hermes_cli.dashboard_auth.token_auth.register_token_route(path)`, which is not on the public list. Something like `ctx.register_token_route(path)`, scoped to the plugin's own `/api/plugins/<id>/` prefix, would cover it and keep plugins from marking anyone else's routes.

2. **A public way to get a local environment and the host's configured `terminal.cwd`.** The backend keeps a `server` target that should behave like the built in local backend, so it builds a `tools.environments.local.LocalEnvironment`. Because Hands sets `is_container = True` so device paths stay isolated from the host, core replaces a host-shaped `TERMINAL_CWD` (`/home/...`, `/Users/...`, or a drive path) with `~` before calling `create_environment` (`tools/terminal_tool.py`), so Hands calls `tools.file_tools_paths._configured_terminal_cwd` to restore the host's configured `terminal.cwd` for `server`. A small public factory on the terminal environment provider API that builds the local environment (with the profile's host `terminal.cwd` when none was recorded yet) would replace both private imports. Public exports of `FileFetchError` (to refuse a MEDIA fetch) and of the background log poll command builder (`log_delta_command`, so a backend can recognise core's own poll) would remove two more.

3. **A way to notify the owner without starting a turn.** When a paired device's local deny list changes, the relay (running in the dashboard process) refuses that device until the owner accepts the change, and it should tell the owner in their chat. `ctx.inject_message` does not fit: it starts an agent turn, needs `allow_gateway_injection`, only works where a gateway injector is live, and needs a session origin shaped like `SessionSource`, which is not public. A public `ctx.notify_owner(text)` (or a `notify` in `hermes_cli.plugin_events`) that sends a plain message to the profile's home channel from any process would cover it. For now the alert shows in `/hands status` and the Desktop pane.

4. **Token routes scoped to the provider that owns them.** The token seam asks every token provider about every registered token route and accepts the first principal it gets (`hermes_cli/dashboard_auth/token_auth.py`), and the drain route reads only `token_principal.principal`, never its provider or scopes (`hermes_cli/web_routers/actions.py`). So a credential that is valid for one plugin also opens every other plugin's token routes and the drain route. For Hands that means a fresh bearer signed by a paired or revoked device key, an unused pairing code, or the gateway's local bearer passes the token check on routes that have nothing to do with Hands. A revoked key keeps that until 1 hour after the relay first sends its signed stop reply, or 7 days if the device never contacts the relay again. Hands already returns None for anything it cannot verify, but it cannot tell which route it is being asked about, because `verify_token` gets only the token. A token route registration that names its provider, for example `register_token_route(path, provider=...)` or the `ctx.register_token_route` from ask 1 bound to the calling plugin's provider, with the seam asking only that provider, would close it. Checking the provider and scope in the drain handler would close the drain case on its own.

5. **`strip_env_keys` honoured in the terminal's own spawn env.** A backend provider declares `strip_env_keys` so model-authored commands can never read its credentials (`agent/terminal_env_provider.py`). Core applies them to background and helper processes through `_sanitize_subprocess_env` (`tools/environments/local.py`), but `_make_run_env`, which builds the env for every foreground terminal command, passes `frozenset()` instead. Hands keeps a `server` target that is a plain `LocalEnvironment`, so its relay seed would reach `echo $HANDS_RELAY_SEED` on that target. For now Hands passes `env={"HANDS_RELAY_SEED": ""}` to that `LocalEnvironment` itself. Passing `_plugin_terminal_env_strip_keys()` there, as `_sanitize_subprocess_env` does, would make the declared keys enough on their own.

6. **A public read and update of the session's working folder.** A multi-target backend has to tell whether the `cwd` core passes to `execute()` is an explicit `workdir=`, the session's recorded cwd, or a gateway default, so a device never starts in a folder that only exists on the server. When a conversation switches targets or receives a gateway workspace override while on a device, the backend also has to keep core's recorded session cwd pointed at the active target. Today that takes `tools.approval.get_current_session_key`, `tools.terminal_tool.get_session_cwd`, `tools.terminal_tool.record_session_cwd`, `tools.terminal_tool._get_env_config`, and `tools.terminal_tool.resolve_task_overrides`. Public helpers on the environment or context API to read and update the session's recorded cwd (plus passing `cwd` provenance to `execute()`) would replace all five symbols.

7. **Public target-change and file-tool lifecycle seams.** `ShellFileOperations` caches which executables exist and where `rg` is for whichever machine answered first (`tools/file_operations.py`, `tools/file_operations_search.py`), and `tools.file_tools_read_tracking` keeps a 60-second not-found cache and read-dedup hit counters per session. When a conversation switches targets, Hands drops the old file-operation and read-tracking caches with `tools.file_tools.clear_file_ops_cache` and `tools.file_tools_read_tracking.notify_other_tool_call`. The target-change handler also calls `tools.terminal_tool_lifecycle.get_active_env` to identify the active environment before it clears state. Hands walks Python call frames to identify file-tool calls because `ShellFileOperations._exec` does not mark them when calling `execute()`. A public target-change callback carrying the active environment, `invalidate_file_ops(task_id, session_id)`, and a `file_op=True` marker on file-tool `execute()` calls would replace these workarounds.

8. **`~` resolved through the environment for plugin backends.** File tools expand `~` with the gateway's own home (`_expand_tilde`, `tools/file_tools_paths.py`), so on a plugin backend whose machine has a different home, a `~/x` path is reported as the gateway user's home in `resolved_path`, even though Hands writes it under the device home. The SSH backend already resolves `~` against the remote's detected home (`_ssh_remote_home` and `_resolve_ssh_path`). The same lookup through an environment attribute, such as a `remote_home` a plugin environment can report, would fix it for every plugin backend.

9. **A public read of the profile's effective `terminal.backend`.** `/hands use` and `hermes hands doctor` check whether the profile's effective `terminal.backend` is `hands` before letting the user select a device, including when the backend comes from `TERMINAL_ENV` in the profile `.env` or launch environment rather than `config.yaml`. Today that calls `tools.terminal_scope.build_profile_terminal_scope`, which is private and loads `TERMINAL_*` keys from `.env`. A small public helper (for example `ctx.get_terminal_backend()`) would let backend plugins check whether they are active without importing `tools.terminal_scope`.

10. **A public query of the approval state.** In a witness session Hands asks the helper to approve every tool call that reaches the device, so it must refuse device tools when nobody will be asked: approvals bypassed for the session, yolo mode, or an unattended context whose mode approves on its own. Today that takes `tools.approval.is_approval_bypass_active_for_session`, `tools.approval._yolo_active` and `tools.approval._unattended_contexts`. A public `ctx.approval_state(session_key)` that says whether a `pre_tool_call` "approve" will reach a person would replace all three.

11. **A public check of other hooks and middleware.** A `pre_tool_call` hook that returns "approve" with a message cannot know whether another plugin's `pre_tool_call` hook or `tool_execution` middleware will change the call after the person approved what they saw. Hands reads `ctx._manager._hooks` and `ctx._manager._middleware` and blocks device tools in a witness session when anything else is registered. Two plugins that ship with Hermes, security-guidance and disk-cleanup, register such hooks, so a user with either enabled has to disable it for the session. Either a guarantee that arguments are frozen once an approval is shown, or a public `ctx.registered_callbacks(kind)` listing, would replace that.

12. **Public message injection checks.** The help poller runs only where a gateway injector exists, and the relay refuses a device message when the owner has not set `allow_gateway_injection`. Today that reads `ctx._manager.has_gateway_message_injector` and the plugin context's `_gateway_injection_allowed`. Public `ctx.can_inject_messages()` and `ctx.injection_allowed()` would replace both.

13. **Public approval display helpers.** Every approval surface shows the redacted copy of the approval text, so a witness approval whose text redaction would change could show the helper something other than what runs. Hands refuses such calls using `agent.redact.redact_approval_display` and `agent.redact.sanitize_command_for_display`, and it builds the approval from arguments coerced with `tools.arg_coercion.coerce_tool_args`, because the agent path coerces only after the hook runs. Public exports of those three functions, or coercion before `pre_tool_call` runs, would remove them.

Two smaller questions, no change needed:

1. Rule 11 covers credentials a plugin reads. The device agent is a separate Python package, installed with pipx from the same repository, that keeps its own private key in the OS keyring or an owner only file on the device, and the gateway side stores only device public keys plus one relay seed declared as a `config_schema` secret and read with `get_secret`. Is that the shape you want for plugins with a companion agent?
2. Rule 17 allows a binary a user's machine fetches at setup time from the official source. Do compiled wheels from PyPI that the companion package depends on (psutil, cryptography, mss and Pillow) fall under that, or is anything more expected?

Happy to send PRs for any of these seams. Thanks for the plugin system.
